Docker Basics

Containers, images, workflow, and commands

Docker is an open platform for developing, shipping, and running applications, and it uses containers as the unit for distributing and testing software across environments.

What Docker gives you

Containers package application code with dependencies, while Docker provides tooling to build, run, and distribute them.

📦

Image

A read-only template used to create containers.

docker pull nginx
▶️

Container

A runnable instance of an image with its own isolated process.

docker run nginx
🔌

Client + daemon

Docker uses a client-server architecture where the client talks to the daemon.

docker ps

Core workflow

A typical Docker flow is write a Dockerfile, build an image, run a container, and optionally publish the image to a registry.

1

Write

Define base image, files, ports, and startup command.

Dockerfile
2

Build

Turn the Dockerfile into a reusable image.

docker build -t myapp .
3

Run

Start a container and map ports to the host.

docker run -p 8000:8000 myapp
4

Share

Push the image to a registry for other systems.

docker push myrepo/myapp

Useful commands

Build and run

  • docker build -t myapp .
  • docker run -d -p 8000:8000 myapp
  • docker ps
  • docker stop <container_id>

Inspect and clean up

  • docker images
  • docker logs <container_id>
  • docker exec -it <container_id> sh
  • docker rm <container_id>

`docker run` creates and starts a new container from an image, while `docker build .` uses the current directory as the build context.

Why teams use Docker

1

Consistent packaging

The same image can move from laptop to test to production.

2

Lightweight runtime

Containers share the host kernel rather than bundling a full guest OS.

3

Fast delivery

A container workflow simplifies testing, deployment, and scaling.
